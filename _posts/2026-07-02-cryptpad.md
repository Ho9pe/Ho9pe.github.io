## Background Theory

### 1. RC4 Stream Cipher

RC4 (Rivest Cipher 4) is a symmetric stream cipher designed by Ron Rivest in 1987. It was widely used in protocols like WEP and TLS, though it's now considered insecure.

**How RC4 Works:**

#### Key Scheduling Algorithm (KSA)

```
Initialize S-box (256 bytes) with values 0-255
For i from 0 to 255:
    j = (j + S[i] + key[i mod keylength]) mod 256
    Swap S[i] and S[j]
```

The KSA creates a permutation of all 256 possible bytes based on the key.

#### Pseudo-Random Generation Algorithm (PRGA)

```
i = 0, j = 0
For each byte in plaintext:
    i = (i + 1) mod 256
    j = (j + S[i]) mod 256
    Swap S[i] and S[j]
    K = S[(S[i] + S[j]) mod 256]
    Output = plaintext[byte] XOR K
```

The PRGA generates a pseudo-random keystream that is XORed with the plaintext to produce ciphertext.

**Properties:**

- Stream cipher (encrypts byte-by-byte)
- Symmetric (same key for encryption/decryption)
- Fast and simple to implement
- Variable key size (1-256 bytes)

### 2. Windows PE File Structure

The executable is a Windows Portable Executable (PE) file containing:

- **Import Address Table (IAT):** Lists external functions from DLLs
- **.text section:** Executable code
- **.data section:** Initialized data (strings, global variables)
- **Resources:** Icons, menus, dialogs

**Relevant Windows APIs used:**

- **KERNEL32.dll:** File I/O, memory management
- **USER32.dll:** GUI operations (windows, dialogs, messages)
- **ADVAPI32.dll:** `SystemFunction036` (RtlGenRandom - cryptographically secure RNG)
- **COMDLG32.dll:** Common dialogs (file save/open)

## Deep Dive: Encryption Routine Analysis

### Function: `sub_4013BD` - Main Encryption Logic


```c
BOOL sub_4013BD()
{
    // Get text length from the notepad window
    NumberOfBytesWritten = GetWindowTextLengthA(dword_4024D1) + 1;
    
    // Calculate padding to make length a multiple of 64
    RandomBufferLength = 64 - NumberOfBytesWritten % 0x40;
    
    // Allocate buffer
    lpMem = HeapAlloc(hHeap, 0, NumberOfBytesWritten + RandomBufferLength);
    
    // Get the plaintext
    GetWindowTextA(dword_4024D1, lpMem, NumberOfBytesWritten);
    
    // Generate random padding
    sub_40166B(&lpMem[NumberOfBytesWritten], RandomBufferLength);
    
    // Generate random 8-byte key
    sub_40166B(&byte_4024C5, 8u);
    
    // Encrypt!
    v3 = sub_4014EB(lpMem, NumberOfBytesWritten, 1);
    
    // Write to file
    WriteFile(hObject, lpMem, v3, &NumberOfBytesWritten, 0);
}
```

**Key Discovery 1:** The encryption uses a randomly generated 8-byte key stored at `byte_4024C5`.

**Key Discovery 2:** `sub_40166B` is just a wrapper around `SystemFunction036`:

```c
BOOLEAN sub_40166B(PVOID RandomBuffer, ULONG RandomBufferLength)
{
    return SystemFunction036(RandomBuffer, RandomBufferLength);
}
```

This generates cryptographically secure random bytes.

### Function: `sub_4014EB` - The Encryption Algorithm

This function implements a custom encryption scheme. Let's break it down:

#### Parameter Analysis

```c
char sub_4014EB(_BYTE *a1,  // Data buffer
                int a2,      // Data length
                int a3)      // Mode: 1 = encrypt, 0 = decrypt
```

#### Encryption Mode (`a3 = 1`)

**Step 1: First XOR Pass**

```c
v7 = a1;
v8 = byte_4024C5;  // 8-byte key
v9 = NumberOfBytesWritten;
LABEL_6:
v10 = 0;
do {
    *v7++ ^= *v8++;  // XOR with key
    if (++v10 == 8)
        goto LABEL_6;  // Repeat key every 8 bytes
    --v9;
} while (v9);
```

This XORs the entire plaintext with the 8-byte key, repeating the key cyclically.

**Step 2: RC4 Encryption**

Initialize S-box:

```c
v11 = 256;
do {
    byte_403795[(unsigned __int8)-(char)v11] = -(char)v11;
    --v11;
} while (v11);
```

This initializes the S-box with values 0-255.

Key Scheduling Algorithm (KSA):

```c
// Expand key to 256 bytes by repeating it
v12 = &unk_403695;
v13 = 256;
v14 = 0;
do {
    if (v14 >= 8)
        v14 = 0;
    *v12++ = byte_4024C5[v14++];
    --v13;
} while (v13);

// Permute S-box based on key
v15 = 0;
v16 = v12 - 256;
v17 = 0;
v18 = 256;
do {
    LOBYTE(v15) = byte_403795[v17] + v16[v17] + v15;
    v19 = byte_403795[v17];
    byte_403795[v17] = byte_403795[v15];
    byte_403795[v15] = v19;
    ++v17;
    --v18;
} while (v18);
```

This is the standard RC4 KSA - it creates a permutation of the S-box based on the key.

Pseudo-Random Generation Algorithm (PRGA):

```c
v20 = a1;
v21 = 0;
v22 = 0;
v23 = a2;
do {
    v24 = (unsigned __int8)(v21 + 1);
    v25 = byte_403795[v24];
    LOBYTE(v22) = v25 + v22;
    v26 = byte_403795[v22];
    byte_403795[v24] = v26;
    byte_403795[v22] = v25;
    LOBYTE(v24) = byte_403795[(unsigned __int8)(v25 + v26)] ^ a1[v21];
    v20[v21++] = v24;
    --v23;
} while (v23 != 1);
```

Standard RC4 PRGA - generates keystream and XORs with data.

**Step 3: Second XOR Pass**

```c
v27 = a1;
v28 = byte_4024C5;
v29 = NumberOfBytesWritten;
LABEL_20:
v30 = 0;
do {
    result = *v28 ^ *v27;
    *v27++ = result;
    ++v28;
    if (++v30 == 8)
        goto LABEL_20;
    --v29;
} while (v29);
```

XOR the result with the key again - creating a "double XOR + RC4 sandwich."

**Step 4: Append Metadata**

````c
if (a3 == 1) {
    v31 = &a1[a2 - 13 + RandomBufferLength];
    *(_DWORD *)v31 = a2;                    // Original length (4 bytes)
    v31 += 4;
    qmemcpy(v31, byte_4024C5, 8u);         // THE KEY! (8 bytes)
    v31[8] = 8;                             // Padding length (1 byte)
    return RandomBufferLength + a2;
}
```

**CRITICAL VULNERABILITY:** The encryption key is appended to the encrypted file!

#### File Format
```
[Encrypted Data] [Original Length (4 bytes)] [Key (8 bytes)] [Padding (1 byte)]
                                              ^^^^^^^^^^^^^^^
                                              THE VULNERABILITY!
````

### Why This Is a Vulnerability

The developer made a fatal design flaw:

**Goal:** Use unique random keys for each file (good security practice)  
**Problem:** How to decrypt without remembering the key?  
**"Solution":** Store the key in the file itself  
**Result:** Complete security failure - anyone with the file has the key!

This is like:

- Locking your door and leaving the key under the doormat
- Encrypting your password and storing it next to the encrypted password
- Hiding treasure and drawing a map to it

## Exploitation Strategy

### Step 1: Extract Metadata from flag.enc

```bash
$ xxd -l 13 -s -13 flag.enc
00000033: 1c00 0000 e817 1bf4 503f 3d70 08
```

Parsing (little-endian):

- **Bytes 0-3:** `1c 00 00 00` → `0x0000001C` = **28 bytes** (original length)
- **Bytes 4-11:** `e8 17 1b f4 50 3f 3d 70` → **Encryption key!**
- **Byte 12:** `08` → **8 bytes** of padding

### Step 2: Understand Decryption Mode

Looking at the decrypt branch (`a3 = 0`):

```c
v3 = *(_DWORD *)&a1[a2 - 1];           // Read padding length
v4 = &a1[a2 - 1 - v3];                  // Calculate key position
qmemcpy(byte_4024C5, v4, v3);          // Extract key from file!
v5 = *((_DWORD *)v4 - 1);               // Read original length
*((_DWORD *)v4 - 1) = 0;
a2 = v5;
```

The decryption function:

1. Reads metadata from the end of the file
2. Extracts the key
3. Runs the same algorithm (XOR → RC4 → XOR is self-inverse)

### Step 3: Implement Decryption

Since we have the key, we can decrypt manually:

```python
#!/usr/bin/env python3

# Read the encrypted file
with open('flag.enc', 'rb') as f:
    data = f.read()

# Extract metadata from last 13 bytes
original_length = int.from_bytes(data[-13:-9], 'little')
key = data[-9:-1]  # 8 bytes
padding_length = data[-1]

print(f"Original length: {original_length}")
print(f"Key: {key.hex()}")
print(f"Padding: {padding_length}")

# Remove metadata (last 13 bytes)
encrypted = bytearray(data[:-13])

# Step 1: XOR with key (first pass - reverse of encryption step 3)
for i in range(len(encrypted)):
    encrypted[i] ^= key[i % 8]

# Step 2: RC4 decrypt (RC4 is symmetric - same operation for encrypt/decrypt)
def rc4_crypt(data, key):
    # Initialize S-box with values 0-255
    S = list(range(256))
    
    # Key Scheduling Algorithm (KSA)
    j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) % 256
        S[i], S[j] = S[j], S[i]
    
    # Pseudo-Random Generation Algorithm (PRGA)
    result = bytearray()
    i = j = 0
    for byte in data:
        i = (i + 1) % 256
        j = (j + S[i]) % 256
        S[i], S[j] = S[j], S[i]
        K = S[(S[i] + S[j]) % 256]
        result.append(byte ^ K)
    
    return result

decrypted = rc4_crypt(encrypted, key)

# Step 3: XOR with key again (reverse of encryption step 1)
for i in range(len(decrypted)):
    decrypted[i] ^= key[i % 8]

# Step 4: Remove padding and extract original plaintext
flag = decrypted[:original_length]

print(f"\nDecrypted flag: {flag.decode('ascii')}")
```
